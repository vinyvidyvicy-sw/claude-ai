Panduan Deploy ke Lab VMware ESXi dan Pengujian

Cisco & Splunk Lab Portal: dari GitHub ke VM backend web server, lalu uji di server, Mac, dan laptop Windows

Tujuan. Mengambil kode dari GitHub, menjalankannya di sebuah VM di lab VMware ESXi sebagai backend web server, lalu mengujinya dari server itu sendiri (localhost), dari Mac, dan dari laptop Windows. Portal berjalan dalam mode DRY-RUN: tidak ada perangkat yang disentuh. Semua perintah di bawah belum dicoba di ESXi Anda; skrip uji dan konfigurasi sudah dicoba di sandbox Linux (HTTP dan HTTPS self-signed).
Laptop Mac / Windows │ HTTPS 443 ▼ [ VM di ESXi: Ubuntu Server ] nginx (TLS) ──127.0.0.1:8000──> portal (uvicorn + systemd) └─ data/portal.db (pengguna, audit) VM ──SSH 22 atau 443──> GitHub (deploy key, hanya-baca) VM ──HTTPS 443──> pypi.org (pip install)

1. Buat VM di ESXi

1Unggah ISO.

Buka ESXi Host Client (https://<IP-ESXi>), menu Storage, pilih datastore, Datastore browser, Upload, lalu pilih ISO Ubuntu Server 24.04.

2Buat VM.

Virtual Machines, Create / Register VM, Create a new virtual machine. Nama: portal-lab-01. Guest OS family: Linux, version: Ubuntu Linux (64-bit). Pilih datastore.

Customize settings: CPU 2, Memory 4 GB, Hard disk 40 GB (Thin provisioned), Network Adapter: port group lab Anda, CD/DVD Drive: Datastore ISO file (pilih ISO tadi) dan centang Connect at power on. Klik Finish.

3Instal Ubuntu.

Power on, buka Console. Di installer: atur IP tetap (atau DHCP), buat pengguna admin, dan centang Install OpenSSH server. Setelah selesai, lepas ISO dan reboot.

4Snapshot awal.

Setelah VM bisa login dan SSH berjalan, ambil Snapshot bernama bersih-sebelum-portal. Anda dapat kembali ke kondisi ini bila ada yang salah.

2. Siapkan server

Dari Mac atau Windows, masuk lewat SSH (PowerShell dan Terminal macOS sudah punya ssh):

ssh <pengguna-admin>@<IP-VM>
1Pembaruan dan paket.
sudo apt update && sudo apt -y upgrade
sudo apt -y install python3 python3-venv python3-pip git nginx openssl ufw open-vm-tools
python3 --version        # harus 3.11 atau lebih baru
2Waktu.

Waktu yang benar penting untuk batas waktu sesi dan catatan audit. Zona waktu di bawah adalah ASSUMPTION.

sudo timedatectl set-timezone Asia/Jakarta
timedatectl            # "System clock synchronized: yes"
3Pengguna layanan (tanpa hak root).
sudo useradd --system --create-home --home-dir /opt/portal --shell /bin/bash portal
sudo -u portal -H mkdir -p /opt/portal/.ssh
sudo chmod 700 /opt/portal/.ssh
4Firewall.
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
# lebih ketat (disarankan): izinkan 443 hanya dari subnet lab
# sudo ufw allow from <SUBNET-LAB>/24 to any port 443 proto tcp
Port 8000 tidak dibuka. Hanya nginx (80/443) yang boleh dijangkau dari luar VM.

3. Hubungkan server ke GitHub dan ambil kode

Repo: vinyvidyvicy-sw/claude-ai, branch ccr-5a472752-cizl40. Cara yang disarankan untuk server adalah deploy key (kunci SSH khusus, hanya-baca, hanya untuk satu repo), bukan akun pribadi.

3.1 Cek koneksi keluar

curl -sI https://github.com | head -1        # HTTP/2 200
curl -sI https://pypi.org | head -1          # HTTP/2 200

3.2 Buat kunci SSH untuk pengguna portal

sudo -u portal -H ssh-keygen -t ed25519 -C "portal-lab-deploy" -f /opt/portal/.ssh/id_ed25519 -N ""
sudo cat /opt/portal/.ssh/id_ed25519.pub     # salin seluruh barisnya
Kunci tanpa passphrase karena layanan berjalan tanpa interaksi. Risikonya dibatasi dengan membuatnya hanya-baca di GitHub (langkah berikut). Jangan salin kunci privat (file tanpa .pub) ke mana pun.

3.3 Daftarkan sebagai Deploy key di GitHub

  1. Buka repo di GitHub, lalu Settings, Deploy keys, Add deploy key.
  2. Title: portal-lab-01. Key: tempel isi file .pub.
  3. Jangan centang Allow write access. Klik Add key.

Menu ini hanya terlihat oleh pemilik atau admin repo.

3.4 Uji koneksi

sudo -u portal -H ssh -T git@github.com

Pertama kali akan muncul pertanyaan fingerprint. Bandingkan dengan fingerprint resmi di dokumentasi GitHub (cari "GitHub's SSH key fingerprints") sebelum mengetik yes. Hasil yang benar: Hi vinyvidyvicy-sw/claude-ai! You've successfully authenticated, but GitHub does not provide shell access.

Jika port 22 diblokir, pakai SSH lewat port 443:

sudo -u portal -H tee /opt/portal/.ssh/config >/dev/null <<'EOF'
Host github.com
  Hostname ssh.github.com
  Port 443
  User git
EOF
sudo chmod 600 /opt/portal/.ssh/config

3.5 Ambil kode

sudo -u portal -H git clone git@github.com:vinyvidyvicy-sw/claude-ai.git /opt/portal/claude-ai
cd /opt/portal/claude-ai
sudo -u portal -H git checkout ccr-5a472752-cizl40
sudo -u portal -H git log --oneline | head -3
Alternatif tanpa deploy key: HTTPS dengan fine-grained personal access token (hanya repo ini, izin Contents: Read-only, punya tanggal kedaluwarsa). Token itu rahasia: jangan ditulis di skrip, chat, atau email. Deploy key lebih disarankan untuk server.

4. Pasang aplikasi

1Lingkungan Python dan dependensi.
cd /opt/portal/claude-ai
sudo -u portal -H python3 -m venv .venv
sudo -u portal -H .venv/bin/pip install --upgrade pip
sudo -u portal -H .venv/bin/pip install -r requirements.txt
sudo -u portal -H mkdir -p data
2Inventaris perangkat lab.

Salin contoh lalu isi perangkat sungguhan (nama, platform, alamat). File ini tidak ikut ke Git. Portal tidak menyimpan kredensial perangkat.

sudo -u portal -H cp config/inventory.example.yaml config/inventory.yaml
sudo -u portal -H nano config/inventory.yaml

Di file yang sama Anda bisa menambah launchers: (misalnya alamat Ekahau Design dan Document Procurement). Lihat komentar di dalam file.

3Konfigurasi lingkungan.
sudo mkdir -p /etc/portal
sudo cp deploy/portal.env.example /etc/portal/portal.env
sudo chown root:portal /etc/portal/portal.env
sudo chmod 640 /etc/portal/portal.env
sudo nano /etc/portal/portal.env
Tahap A (uji HTTP di server dulu): ubah menjadi PORTAL_COOKIE_SECURE=false. Setelah nginx HTTPS aktif (bagian 6), kembalikan ke true. Biarkan PORTAL_EXECUTION_MODE=dry_run.
4Buat admin pertama.
sudo -u portal -H bash -c 'set -a; . /etc/portal/portal.env; set +a; cd /opt/portal/claude-ai && .venv/bin/python -m app.cli create-admin admin'

Isi kata sandi (minimal 12 karakter) dua kali. Kata sandi tidak tampil saat diketik dan tidak disimpan dalam bentuk teks biasa.

5. Jalankan sebagai layanan (systemd) dan uji HTTP di server

sudo cp deploy/portal.service /etc/systemd/system/portal.service
sudo systemctl daemon-reload
sudo systemctl enable --now portal
sudo systemctl status portal --no-pager         # active (running)
curl -s http://127.0.0.1:8000/healthz           # ok
sudo journalctl -u portal -n 30 --no-pager      # log aplikasi

Layanan hanya mendengarkan 127.0.0.1:8000 (tidak terlihat dari jaringan), berjalan sebagai pengguna portal, hanya boleh menulis ke folder data, dan hidup otomatis setelah reboot.

Uji cepat Tahap A (di server):

python3 scripts/smoke_test.py http://127.0.0.1:8000 --username admin

6. HTTPS dengan nginx (Tahap B)

Browser dan cookie sesi (bertanda Secure) membutuhkan HTTPS untuk akses dari laptop. Contoh di bawah memakai sertifikat self-signed untuk lab. Untuk lingkungan yang lebih rapi, minta sertifikat dari CA internal organisasi (TODO).

1Buat sertifikat.
sudo mkdir -p /etc/ssl/portal
sudo openssl req -x509 -nodes -newkey rsa:2048 -sha256 -days 365 \
  -keyout /etc/ssl/portal/portal.key -out /etc/ssl/portal/portal.crt \
  -subj "/CN=portal.lab.local" \
  -addext "subjectAltName=DNS:portal.lab.local,IP:<IP-VM>"
sudo chmod 600 /etc/ssl/portal/portal.key
2Pasang konfigurasi nginx.
cd /opt/portal/claude-ai
sudo cp deploy/nginx-portal.conf /etc/nginx/sites-available/portal
sudo sed -i 's/PORTAL_HOST/portal.lab.local/g' /etc/nginx/sites-available/portal
sudo ln -s /etc/nginx/sites-available/portal /etc/nginx/sites-enabled/portal
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

Jika Anda memakai IP saja (tanpa nama), ganti portal.lab.local dengan <IP-VM>.

3Aktifkan cookie Secure.
sudo sed -i 's/^PORTAL_COOKIE_SECURE=.*/PORTAL_COOKIE_SECURE=true/' /etc/portal/portal.env
sudo systemctl restart portal
4Nama portal di laptop (jika belum ada di DNS).

Tambahkan baris <IP-VM> portal.lab.local ke file hosts: Mac di /etc/hosts (sudo nano /etc/hosts); Windows di C:\Windows\System32\drivers\etc\hosts (buka Notepad sebagai Administrator).

5Percayai sertifikat (opsional, menghilangkan peringatan browser).

Ambil sertifikat: scp <pengguna>@<IP-VM>:/etc/ssl/portal/portal.crt .

Mac: klik dua kali portal.crt, Keychain Access, cari "portal.lab.local", Get Info, Trust, Always Trust.
Windows: PowerShell sebagai Administrator: certutil -addstore -f Root portal.crt.
Tanpa langkah ini browser tetap bisa dipakai setelah Anda memilih Lanjutkan / Proceed pada peringatan.

7. Pengujian

7A. Di server (localhost)

systemctl is-active portal nginx                         # active  active
curl -s http://127.0.0.1:8000/healthz                    # ok

curl -skI https://127.0.0.1/ | head -3                   # 303 -> /login
ss -tlnp | grep -E ':(80|443|8000)\b'                    # 8000 hanya di 127.0.0.1
cd /opt/portal/claude-ai

Opsional, uji otomatis kode (38 tes):

7B. Dari Mac

ping -c 3 <IP-VM>
nc -vz <IP-VM> 443                                       # succeeded
# Browser: https://portal.lab.local  (atau https://<IP-VM>)
# Uji otomatis (salin skripnya atau clone repo di Mac):
python3 scripts/smoke_test.py https://portal.lab.local --username admin --insecure

Akses lewat "localhost" di Mac (terowongan SSH), berguna bila port 443 tidak terbuka ke laptop Anda:

ssh -N -L 8443:127.0.0.1:443 <pengguna>@<IP-VM>          # biarkan terbuka
# Browser: https://localhost:8443   (peringatan sertifikat: lanjutkan)

7C. Dari laptop Windows (PowerShell)

Test-NetConnection <IP-VM> -Port 443                     # TcpTestSucceeded : True
# Browser: https://portal.lab.local  (atau https://<IP-VM>)
python scripts\smoke_test.py https://portal.lab.local --username admin --insecure
# (jika "python" tidak dikenali, pakai: py scripts\smoke_test.py ...)
# Terowongan SSH ke "localhost" (OpenSSH bawaan Windows 10/11):
ssh -N -L 8443:127.0.0.1:443 <pengguna>@<IP-VM>
# Browser: https://localhost:8443
Terowongan ke port 443 (bukan 8000) dipakai agar cookie Secure tetap berfungsi. Jika memakai http://localhost:8000 lewat terowongan ke port 8000, Anda harus mengatur PORTAL_COOKIE_SECURE=false dan beberapa browser (terutama Safari) tetap bisa menolak login.

9. Masalah umum

GejalaPenyebab dan solusi
Permission denied (publickey) saat cloneDeploy key belum ditambahkan, salah repo, atau perintah tidak dijalankan sebagai pengguna portal. Cek: sudo -u portal -H ssh -vT git@github.com
Clone/pip time outPort 22 atau internet diblokir. Pakai SSH port 443 (3.4), atur proxy (pip --proxy, git config http.proxy), atau jalur offline (3.6)
systemctl status portal gagalLihat journalctl -u portal -n 50. Penyebab umum: path salah di portal.env, .venv belum dibuat, inventory.yaml salah format
Error menulis database / readonly databaseFolder data bukan milik portal: sudo chown -R portal:portal /opt/portal/claude-ai/data
nginx 502 Bad GatewayPortal tidak berjalan: sudo systemctl restart portal lalu cek log
Login tidak berpengaruh (kembali ke form)Cookie Secure lewat HTTP biasa. Pakai HTTPS, atau Tahap A dengan PORTAL_COOKIE_SECURE=false hanya untuk uji di server
Peringatan sertifikat di browserNormal untuk self-signed. Percayai sertifikat (6.5) atau gunakan sertifikat CA internal
Tidak bisa menjangkau 443 dari laptopCek ufw status, port group ESXi, firewall jaringan lab; Test-NetConnection atau nc -vz dari laptop
Python di Ubuntu 22.04 terlalu lama (3.10)Gunakan Ubuntu 24.04, atau pasang Python 3.11+ (mis. dari PPA deadsnakes) lalu buat ulang .venv
Waktu di log salahPerbaiki NTP/zona waktu (bagian 2.2); VM di ESXi juga sebaiknya sinkron waktu
Gambar topologi/logo tidak munculPastikan file ada di app/static/img pada branch yang benar; hard-refresh browser

10. Catatan keamanan dan item terbuka

  • Halaman login bisa dibuka tanpa masuk dan memuat gambar topologi lab. Tempatkan portal di jaringan lab/internal dan batasi sumber lewat firewall.
  • Portal tidak memegang kredensial perangkat; backend otomasi yang akan melakukannya (belum ada, TODO). Mode live jangan diaktifkan sebelum itu ada dan disetujui.
  • Deploy key bersifat hanya-baca; cabut dari GitHub (Settings, Deploy keys) bila VM dihentikan.
  • Branch ccr-5a472752-cizl40 belum digabung ke branch utama. Setelah disetujui, gabungkan lewat pull request agar server cukup git pull tanpa checkout.
