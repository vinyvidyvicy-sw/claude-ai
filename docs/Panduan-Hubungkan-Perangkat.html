Panduan Menghubungkan Perangkat ke Portal

Cisco & Splunk Lab Portal: klik dari dashboard langsung ke konsol tiap perangkat

Tujuan. Setelah layanan tiap perangkat menyala dan punya IP, user cukup membuka dashboard portal, memilih platform, lalu klik Buka konsol pada perangkat yang diinginkan. Konsol perangkat itu terbuka di tab baru dan konfigurasi dilakukan di sana. Portal ini adalah front end: portal tidak mengonfigurasi perangkat, tidak menyimpan kredensial perangkat, dan tidak menjadi proxy. Panduan ini belum dicoba pada perangkat nyata; fiturnya sudah diuji otomatis (37 tes) dengan alamat contoh.

1. Cara kerjanya

Dashboard portal ── tile platform ──> halaman platform ── "Buka konsol" ──> /console/<nama-perangkat> (portal mencatat siapa, perangkat mana, kapan) │ pengalihan (HTTP 303) ▼ Browser user langsung ke https://<IP-atau-nama-perangkat> (konsol bawaan perangkat)
  • Alamat konsol disimpan di config/inventory.yaml (file lokal, tidak ikut ke Git), bukan di kode.
  • Portal hanya mengalihkan browser. Jadi laptop user harus bisa menjangkau IP perangkat, dan user login memakai akun bawaan perangkat.
  • Setiap klik dicatat di Log audit sebagai device.console_open.

3. Langkah-langkah

1Susun daftar perangkat.

Isi tabel ini (template kosong ada di bagian 9). Kolom platform harus salah satu ID di bawah:

PlatformID di inventory.yaml
Cisco ISEise
Cisco SDA (Catalyst Center)sda
Cisco ACI (APIC)aci
Cisco NX-OS switchesnxos
Cisco Catalyst switches (IOS-XE)catalyst
Splunk Enterprise Securitysplunk
VMware ESXi managementesxi

Nama perangkat: huruf/angka, boleh . _ -, maksimal 63 karakter, harus unik.

2Buka file inventaris.
# Di server portal (ESXi/Ubuntu):
sudo -u portal -H nano /opt/portal/claude-ai/config/inventory.yaml

# Di Mac (uji lokal):        nano ~/claude-ai/config/inventory.yaml
# Di Windows (uji lokal):    notepad claude-ai\config\inventory.yaml

Jika file belum ada, salin dulu dari contoh: cp config/inventory.example.yaml config/inventory.yaml (Windows: copy).

Bila inventory.yaml tidak ada, portal memakai inventory.example.yaml berisi IP placeholder 192.0.2.x. Pastikan file sungguhan sudah dibuat.
3Isi perangkat dan alamat konsolnya.
devices:
  - name: ise-lab-1
    platform: ise
    address: 10.10.1.10
    console_url: "https://10.10.1.10"
  - name: dnac-lab-1
    platform: sda
    address: 10.10.1.11
    console_url: "https://10.10.1.11"
  - name: apic-lab-1
    platform: aci
    address: 10.10.1.12
    console_url: "https://10.10.1.12"
  - name: nxos-lab-1
    platform: nxos
    address: 10.10.1.13
    console_url: "https://10.10.1.13"
  - name: cat-lab-1
    platform: catalyst
    address: 10.10.1.14
    console_url: "https://10.10.1.14"
  - name: splunk-lab-1
    platform: splunk
    address: 10.10.1.15
    console_url: "https://10.10.1.15:<port>"
  - name: esxi-lab-1
    platform: esxi
    address: 10.10.1.16
    console_url: "https://10.10.1.16"
Nilai di atas hanya contoh format. Ganti IP, port, dan path dengan alamat yang Anda pakai di browser untuk konsol tiap perangkat. console_url wajib diawali https://; kalau tidak, portal menolak start dan menampilkan pesan kesalahan. Jangan menaruh kata sandi atau token di file ini.
4(Opsional) Alamat Ekahau Design.

Di file yang sama, bagian launchers::

launchers:
  ekahau:
    url: https://<alamat-ekahau-design>

Kunci yang tersedia: ekahau. Alamatnya wajib diawali https://.

5Mulai ulang portal.
# Server:
sudo systemctl restart portal
sudo journalctl -u portal -n 20 --no-pager     # tidak ada error

# Mac (hentikan dengan Ctrl+C lalu):
cd ~/claude-ai && source .venv/bin/activate
export PORTAL_COOKIE_SECURE=false
python -m uvicorn app.main:app_factory --factory --port 8000

# Windows PowerShell:
cd claude-ai ; .\.venv\Scripts\Activate.ps1
$env:PORTAL_COOKIE_SECURE = "false"
python -m uvicorn app.main:app_factory --factory --port 8000
6Uji dari dashboard.
  1. Masuk ke portal, klik tile platform (mis. Cisco ACI (APIC)).
  2. Di bagian Perangkat dan konsol, perangkat tampil dengan tautan Buka konsol.
  3. Klik. Konsol perangkat terbuka di tab baru. Login dengan akun perangkat.
  4. Kembali ke portal: Log audit (menu admin) menampilkan device.console_open dengan nama Anda dan nama perangkat.

4. Pemeriksaan jaringan dari laptop user

# Mac
nc -vz 10.10.1.12 443                         # succeeded
curl -skI https://10.10.1.12 | head -3        # ada respons HTTP (-k: abaikan sertifikat self-signed)

# Windows PowerShell
Test-NetConnection 10.10.1.12 -Port 443       # TcpTestSucceeded : True
curl.exe -skI https://10.10.1.12

Jika gagal, masalahnya di rute, VLAN manajemen, atau firewall, bukan di portal. Perangkat di VLAN manajemen terpisah memerlukan rute, VPN, atau aturan firewall dari jaringan user.

5. Keamanan dan batasan

  • Tanpa proxy dan tanpa SSO: portal tidak meneruskan kredensial. User login di konsol perangkat dengan akun perangkat. Single sign-on (mis. lewat ISE atau SAML) adalah keputusan terpisah dan bergantung pada dukungan tiap perangkat (TODO).
  • Sertifikat self-signed: browser menampilkan peringatan sekali per perangkat. Percayai sertifikat atau pakai sertifikat dari CA internal.
  • Siapa yang boleh klik: saat ini semua user yang sudah login (Admin, Engineer, Viewer) dapat membuka konsol. Pembatasan per peran belum ada (TODO bila diperlukan). Hak akses sebenarnya tetap ditentukan oleh akun di perangkat.
  • Audit: portal mencatat klik, bukan apa yang dilakukan user di dalam konsol perangkat. Untuk jejak itu, andalkan log perangkat (mis. TACACS+/AAA accounting).
  • Konsol dibuka di tab baru, bukan dibenamkan (iframe), karena perangkat umumnya memblokir pembenaman.
  • File inventory.yaml berisi IP internal; jangan di-commit ke Git (sudah diabaikan oleh .gitignore) dan cadangkan di luar VM.

6. Masalah umum

GejalaPenyebab dan solusi

7. Pengembangan berikutnya (opsional)

  • Satu klik dari tile langsung ke konsol untuk platform yang hanya punya satu perangkat (APIC, Catalyst Center, ISE, dan sebagainya).
  • Status hidup/mati tiap perangkat (cek koneksi sederhana) di halaman platform.
  • Pembatasan tombol konsol per peran, atau per platform.
  • Single sign-on ke konsol perangkat, jika didukung dan disetujui (TODO).
  • Backend otomasi untuk workflow (belum ada). Portal dapat tetap dipakai sebagai peluncur konsol sampai itu siap.

8. Ringkasan satu halaman

  1. Pastikan laptop user bisa menjangkau IP dan port konsol tiap perangkat.
  2. Salin config/inventory.example.yaml menjadi config/inventory.yaml.
  3. Isi name, platform, address, dan console_url (https) untuk tiap perangkat.
  4. (Opsional) isi launchers: untuk Ekahau Design.
  5. sudo systemctl restart portal (atau jalankan ulang di Mac/Windows).
  6. Dashboard, tile platform, Buka konsol. Cek Log audit.
